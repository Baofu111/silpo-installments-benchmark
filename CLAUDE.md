# Бриф проєкту: «Оплата частинами» від кількох банків для Сільпо

## Контекст
У Сільпо вже є «Оплата частинами» від **Банку Восток**. Додається «Оплата частинами» від **ПриватБанку**. Треба в межах одного UI зрозуміло показати кілька варіантів розтермінування від різних банків.

## Мета / критерії успіху
- Пропозиції не виглядають як дублікати.
- Користувач розуміє різницю між банками.
- Вибір банку та кількості платежів простий.

## Обсяг задачі (in scope)
- Бенчмарк 2–3 українських e-commerce з розтермінуванням від кількох банків.
- Аналіз: як показують доступність; як групують банки; як пояснюють умови/кількість платежів; організація вибору в checkout; лого/назви/щомісячний платіж.
- UX-рекомендації для поєднання ПриватБанк + Банк Восток.
- Happy path від вибору оплати до успішного замовлення.
- Швидкий прототип у Figma на основі мобільних скрінів Сільпо.
- Зафіксовані відкриті питання та припущення.

## Поза обсягом (out of scope)
Повний редизайн checkout; фінальний UI; помилки/відмови банку та corner cases; дострокове погашення / керування після оформлення; юридичні тексти; користувацьке тестування.

## Досліджені конкуренти (реальні скріни, Playwright, мобайл 390×844 + десктоп 1440×900)
- **Allo** — список карток-радіо (мобайл) / таблиця 7 банків з колонкою «% по кредиту» (десктоп). Кожен банк зі своєю назвою продукту.
- **MOYO** — вкладки «Без переплати / Кредит, %» (групування за вигодою), далі банк + дропдаун платежів.
- **Ecodrive** — картки з явною «Переплата» і «Всього до сплати»; Monobank + ПриватБанк (2 продукти).
- **Foxtrot** — промо «Оплата частинами» на плитці (контекст).
- **Rozetka** — картка за Cloudflare, не верифіковано.

## Міжнародний контекст (desk research, `INTERNATIONAL.md`)
- **Carrefour + Klarna (FR)** — 1 агрегатор, вибір планів усередині; app one-time card.
- **Woolworths + Zip (AU)** — wallet-модель (Visa-картка/gift card), не inline.
- **Instacart / Walmart (US)** — Instacart: кілька провайдерів окремо; Walmart: ексклюзив (Affirm→Klarna).
- **Rappi / Amazon MX + Kueski** — без картки й історії, біквіклі, аплікація в checkout.
- **Головний висновок:** світова норма — один агрегатор ховає вибір планів, а не ритейлер показує кілька банків. Кейс Сільпо ближчий до UA / LatAm мультибанку. Метод — desk research (retailer-checkout закриті антиботом), умови орієнтовні.

## Ключові рішення (з бенчмарку)
1. Один блок «Оплата частинами», всередині вибір банку (не два способи оплати).
2. Кожен банк = картка-радіо зі своїм лого й **власною назвою продукту**.
3. Кількість платежів — дропдаун у кожній картці, з перерахунком «щомісячно».
4. Щомісячний платіж видно рано (на рівні способу оплати «від X ₴/міс»).
5. Різницю у вартості показувати явно (вкладки або колонка «переплата / 0%»).
6. Десктоп — таблиця-порівняння; мобайл — стек карток.
7. Точки дотику до checkout: показувати щомісячний платіж «від X ₴/міс» вторинною кнопкою на картці товару (не лише на кроці оплати), + банер/мітка для обізнаності.

## Відкриті питання (до фінального UI)
Точні умови банків (платежі/ліміти/переплата); чи потрібен диференціатор назв (обидва «Оплата частинами»); дефолтний банк; платформа-пріоритет; поріг суми; inline vs bottom-sheet; кешбек «Власний рахунок»; потреба ідентифікації до вибору. Деталі — у `RECOMMENDATIONS.md`.
