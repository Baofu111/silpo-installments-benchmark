# UX-рекомендації для Сільпо: «Оплата частинами» ПриватБанк + Банк Восток

> Базується на бенчмарку (`BENCHMARK.md`, реальні скріни Allo / MOYO / Foxtrot) та мобільній візуальній мові Сільпо (`screens/silpo-home.png`).
> Поза межами: повний редизайн checkout, фінальний UI, обробка помилок/відмов банку, дострокове погашення, юртексти. Умови банків нижче — **припущення**, потребують підтвердження.

## Проблема
На кроці оплати з'являються два розтермінування від різних банків (Восток — вже є, Приват — додається). Ризик: виглядають як дублікати; незрозуміла різниця; складний вибір банку та кількості платежів.

## Головні принципи (з бенчмарку)
1. **Один блок «Оплата частинами», а не два окремі способи оплати.** Розтермінування — це один спосіб оплати; всередині — вибір банку. Інакше два майже однакові рядки в списку оплати = відчуття дублікатів.
2. **Кожен банк = окрема картка-радіо** зі своїм брендом. Восток і Приват мають візуально відрізнятися лого й назвою.
3. **Зберігати власну назву продукту банку.** Напр. ПриватБанк — «Оплата частинами». Не уніфікувати в безлике «розтермінування» — саме бренд знімає відчуття дубля (підтверджено Allo).
4. **Кількість платежів — дропдаун у кожній картці.** Дефолт — найпопулярніший строк; одразу перерахунок «щомісячно».
5. **Показувати щомісячний платіж якомога раніше** — на рівні способу оплати («від X ₴/міс»), як робить Allo на кнопці.
6. **Якщо умови двох банків суттєво різні за вартістю** — додати верхній рівень «Без переплати / З переплатою» (патерн MOYO). Якщо обидва без переплати — рівень не потрібен, банки йдуть простим списком.

## Рекомендований склад картки банку
- Радіо-кнопка (обрана → рамка бренд-кольору Сільпо + залите коло).
- Лого банку + назва банку (жирним) + назва продукту (сірим підписом).
- Дропдаун «Кількість платежів» → варіанти конкретного банку.
- «Щомісячно: X ₴» (акцент).
- «Разом: Y ₴» + мітка «Без переплати», якщо застосовно.
- Згортка «Умови» (згорнута за замовчуванням).

## Обов'язкові vs опційні елементи
| Елемент | Статус |
|---|---|
| Лого + назва банку | Обов'язково |
| Назва продукту банку | Обов'язково (антидублікат) |
| Щомісячний платіж | Обов'язково |
| Кількість платежів (дропдаун) | Обов'язково |
| Повна вартість / «без переплати» | Обов'язково |
| Умови (згортка) | Рекомендовано |
| Кешбек «Власний рахунок» | Опційно (перевага Сільпо) |

## Анти-патерни (уникати)
- Два окремі пункти оплати «Розтермінування Восток» і «Розтермінування Приват» на одному рівні зі звичайною оплатою.
- Однакові назви/іконки для обох банків.
- Спільний перемикач кількості платежів на два банки з різними лімітами.
- Ховати щомісячний платіж углиб — його треба бачити при виборі банку.

## Happy path: від вибору оплати до успішного замовлення

Сценарій: користувач у мобільному Сільпо оформлює замовлення, обирає «Оплату частинами» від ПриватБанку (за наявності чинної пропозиції Банку Восток).

1. **Крок оплати в checkout.** У списку способів оплати — пункт **«Оплата частинами»** з підписом-приманкою «від N ₴/міс, 2 банки». Користувач обирає його.
2. **Розкривається блок вибору банку** (inline-акордеон або bottom-sheet) із заголовком «Оберіть банк для оплати частинами».
   - Картка 1: **ПриватБанк — «Оплата частинами»** (лого, дропдаун платежів, «Щомісячно», «Без переплати»).
   - Картка 2: **Банк Восток — «Оплата частинами»** (аналогічно).
   - (Опційно) верхні вкладки «Без переплати / З переплатою», якщо умови різняться.
3. **Користувач обирає ПриватБанк** — картка підсвічується, радіо залите.
4. **Обирає кількість платежів** у дропдауні картки Приват → «Щомісячно» миттєво перераховується.
5. **Sticky-підсумок** унизу оновлюється: «ПриватБанк · 4 платежі · X ₴/міс» + кнопка **«Оформити частинами»**.
6. **Підтвердження замовлення** — користувач тисне CTA; відбувається перехід/редірект у флоу банку (поза межами задачі — деталізація на боці банку).
7. **Екран успіху:** «Замовлення оформлено», нагадування першого платежу/графіка, номер замовлення.

Ключові стани для прототипу: (1) крок оплати зі згорнутим блоком → (2) розкритий вибір банку → (3) обрано Приват + дропдаун платежів → (4) sticky-підсумок → (5) успіх.

## Відкриті питання (уточнити до фінального UI)
1. **Умови банків:** точна к-сть платежів, ліміти суми, наявність переплати/комісії для покупця у Приват і Восток? (визначає, чи потрібен рівень «Без переплати / З переплатою»).
2. **Однакова чи різна назва продукту?** Обидва звуться «Оплата частинами» — чи додавати диференціатор, щоб не злилися?
3. **Пріоритет/дефолт:** який банк обрано за замовчуванням (комерційна домовленість)? Чи є рекомендований?
4. **Платформи:** мобільний застосунок, мобільний веб, десктоп — де запускаємо першим?
5. **Точка входу checkout:** розтермінування доступне для будь-якого кошика чи від порогової суми?
6. **Місце вибору:** inline-акордеон у списку оплати чи окремий bottom-sheet?
7. **Кешбек «Власний рахунок»:** чи діє з розтермінуванням і чи показувати його в картці?
8. **Ідентифікація/скоринг:** чи потрібні дані клієнта до вибору банку (впливає на порядок кроків)?
9. **Rozetka-патерн** не верифіковано скріном — за потреби додати як окреме дослідження.

## Припущення (assumptions)
- Обидва банки пропонують розтермінування **без переплати для покупця** на основний строк (типово для «Оплати частинами»). ← потребує підтвердження.
- Розтермінування рахується на **суму всього замовлення**.
- Прототип — **мобільний** (веб/застосунок), 390px ширина.
- Візуальна мова — з `silpo-home.png` (лого Сільпо, жовті/оранжеві акценти, круглі картки 16px, оранжеві CTA).
