# «Оплата частинами» від кількох банків — UX-дослідження для Сільпо

Бенчмарк і UX-рекомендації: як в одному UI зрозуміло показати розтермінування **ПриватБанку** разом із чинною пропозицією **Банку Восток** у checkout Сільпо, щоб пропозиції не виглядали як дублікати, різниця була зрозумілою, а вибір банку й кількості платежів — простим.

## Досліджені конкуренти
Реальні сторінки, знято через Playwright (мобайл 390×844 + десктоп 1440×900):

- **Allo** — еталон списку кількох банків: модалка «Кредитні пропозиції», картки-радіо (мобайл) / таблиця на 7 банків з колонкою «% по кредиту» (десктоп).
- **MOYO** — групування за вигодою для клієнта: вкладки «Без переплати / Кредит, %».
- **Ecodrive** — прозорість переплати: явні «Переплата» і «Всього до сплати», Monobank + ПриватБанк.
- **Foxtrot** — промо «Оплата частинами» на плитці товару (контекст).
- **Rozetka** — картка товару за Cloudflare, не верифіковано (мобайл і десктоп).

## Ключові висновки
1. Кілька банків = **єдина модалка** зі списком **карток-радіо**, кожен банк окремо.
2. Кожен банк зберігає **власну назву продукту** (антидублікат).
3. Кількість платежів — **дропдаун у кожній картці**.
4. Обов'язково: лого + назва банку + назва продукту + щомісячний платіж + повна вартість.
5. Різницю у вартості показувати явно (вкладки «Без переплати / Кредит, %» або колонка «% по кредиту»).
6. Десктоп — таблиця-порівняння; мобайл — стек карток.
7. Вигоду видно ще до checkout: щомісячний платіж «від X ₴/міс» вторинною кнопкою на картці товару (не лише на кроці оплати).

## Методологія
Скріншоти зроблено з публічних сторінок конкурентів через Playwright (Chromium, uk-UA). Умови банків — орієнтовні, взяті зі скрінів на дату дослідження (2026-07-28), підлягають підтвердженню перед фінальним UI.

## Як відтворити скріни
```bash
npm i -D playwright
npx playwright install chromium
node desktop.mjs   # десктоп-скріни конкурентів
node allo4.mjs     # модалка Allo
# ...інші *.mjs
```
